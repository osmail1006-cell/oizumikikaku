# 週次ブログ更新：実行プロンプト

大泉企画の公開HP https://oizumikikaku.pages.dev/ に、管理会社・賃貸オーナーの役に立つ日本語の清掃・原状回復コラムを1本作成し、公開確認まで行ってください。

## 毎回最初に読むもの
osmail1006-cell/oizumikikaku の最新main、CLAUDE.md、CLAUDE_HANDOFF.md、BLOG_WORKFLOW.md、blog/posts.json、scripts/build-blog.mjs、scripts/build-cloudflare.mjs。

## 重複・競合の防止
- 日本時間の現在日を確認する。記事の掲載日は実際に公開する日。
- blog/posts.jsonに、日本時間の当週（月曜日～日曜日）の日付の新規記事があれば、追加せず既存記事の公開状態を確認する。
- mainに記事があるが本番に未反映なら、同じ内容を別slugで再投稿しない。既存デプロイの状態を確認して報告する。
- 未公開の同じ題材のPRや作業ブランチが見つかった場合も、重複作成を避ける。
- 公開済み記事とタイトルだけでなく内容を比較し、別の1課題を選ぶ。
- 他人の未コミット変更を変更・消去しない。必要なら別クローンまたはworktreeを使う。

## 内容の条件
- 対象：埼玉県・東京都の管理会社・賃貸オーナー。その他関東圏は要相談。
- 1記事1課題。冒頭で答えを述べ、具体的な確認事項、注意点、関連FAQ、実在する問い合わせ導線を含める。
- 未確認の施工実績、料金、所在地、資格、保険、口コミ、営業時間、作業日数、代表者本人による監修を創作しない。
- 地名だけを変えた記事、検索順位操作目的の薄い記事を量産しない。順位・AI引用を保証しない。
- 法令、薬剤、安全手順など一次資料が必要な情報は公式情報で確認し、本文中に出典リンクを付ける。
- 危険なDIY、薬剤混合を勧めない。確かめられない内容を削っても有用なら削って公開する。記事全体の正確性を保てなければ公開しない。
- 写真添付は現行フォームでは受け付けない。必要な写真はメールで相談する案内を守る。
- 既存の /#inquiry を問い合わせ先として利用し、関連する既存記事へのリンクも文脈に応じて付ける。

## 実装・検証
1. blog/posts.json に1件追加する。slugは英小文字・数字・ハイフンで一意にする。title、description、date、HTMLのbodyを設定する。
2. node scripts/build-blog.mjs を実行する。
3. node scripts/build-cloudflare.mjs を実行し、public/内の記事・一覧・リンクを確認する。
4. JSONの構文、slug重複、実在する日付、本文のタグ、canonical、構造化データ、sitemap.xml、feed.xmlを確認する。
5. 記事データ、生成された記事HTML、blog/index.html、sitemap.xml、feed.xmlだけをまとめてコミットする。通常の新規記事では他のファイルを変更しない。
6. 最新origin/mainを再確認してから、既存mainを保持したまま通常pushでmainに反映する。Claudeの作業ブランチにpushしただけで終わらない。権限・保護ルールが妨げる場合は回避せず、PRと原稿を残して報告する。
7. Cloudflare自動公開後に、https://oizumikikaku.pages.dev/blog/<slug>/ の本文・掲載日・canonicalを確認する。新記事が /blog/ と sitemap.xml、feed.xml に現れ、問い合わせリンクが有効な /#inquiry に向いているか確認する。
8. robots.txtが記事の取得を妨げないか確認する。問い合わせの実送信は行わない。
9. デプロイ待ちは回数・時間を区切る。確認できないまま成功としない。

## 報告
日本語で「公開した記事タイトル・URL・今回の要点・確認できた範囲」を短く報告する。
公開できなかったら「阻害要因・作成済み原稿・コミット/PR・未確認の点」を報告する。
1回の成功でこの週次タスクを停止しない。ブログ更新に無関係なフォーム・連絡先・デザイン・画像は変更しない。
